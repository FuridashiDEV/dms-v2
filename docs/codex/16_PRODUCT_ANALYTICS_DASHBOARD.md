# ПУНКТ 16 — PRODUCT ANALYTICS / ADMIN DASHBOARD

## Цель

Цель этого пункта — добавить внутренний dashboard продуктовой аналитики.

После предыдущих пунктов система уже должна уметь:

- работать с организациями;
- хранить документы;
- версионировать документы;
- записывать AuditEvent;
- обрабатывать AI-поля;
- импортировать документы;
- запускать workflow;
- обмениваться документами с контрагентами;
- экспортировать evidence package;
- считать UsageEvent;
- иметь billing foundation.

Теперь нужно сделать слой аналитики, чтобы команда могла видеть:

- сколько организаций активно;
- сколько документов загружено;
- сколько документов обработано AI;
- сколько AI-полей подтверждено;
- сколько workflow запущено и завершено;
- сколько документов отправлено контрагентам;
- сколько контрагентов создано;
- сколько evidence exports сделано;
- какие организации реально используют продукт.

## Главный принцип

Analytics dashboard не должен менять бизнес-логику.

Он должен только читать уже существующие данные и агрегировать их.

Правильная логика:

```text
existing product data
↓
analytics service
↓
dashboard
