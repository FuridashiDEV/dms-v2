# ПУНКТ 1 — АУДИТ ТЕКУЩЕГО ПРОЕКТА

## Цель

Перед любыми изменениями нужно понять текущую архитектуру Django-проекта.

На этом этапе нельзя писать код, создавать миграции, менять модели, менять views, менять templates или проводить рефакторинг.

Задача — только изучить существующий проект и подготовить технический отчёт.

## Главный принцип

Проект нельзя переписывать с нуля.

Все будущие изменения должны наращивать существующий DMS, а не создавать параллельную новую систему.

Codex должен сначала понять, как сейчас работают:

- пользователи;
- роли;
- отделы;
- папки;
- документы;
- типы документов;
- доступы;
- загрузка документов;
- извлечение текста;
- AI-метаданные;
- поиск;
- активность документов;
- формы;
- templates;
- маршруты.

## Что нужно изучить

### 1. Структура проекта

Найти и описать:

- Django apps;
- основные директории;
- settings;
- urls;
- templates;
- static files;
- services;
- tests;
- migrations.

### 2. Модели

Найти и описать все модели, связанные с документооборотом:

- User;
- Department;
- Folder;
- Document;
- DocumentType;
- DocumentActivity;
- DocumentAccess;
- другие связанные модели, если есть.

Для каждой модели указать:

- основные поля;
- связи;
- назначение;
- где используется;
- возможные риски изменения.

### 3. Flow загрузки документа

Нужно восстановить полный путь:

```text
user opens upload page
↓
form validates input
↓
file is saved
↓
text is extracted
↓
AI parser may run
↓
metadata is saved
↓
activity is recorded
↓
user is redirected
