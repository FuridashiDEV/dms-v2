# ПУНКТ 2 — СТАБИЛИЗАЦИЯ ЯДРА DMS

## Цель

Цель этого пункта — стабилизировать существующий DMS перед дальнейшей эволюцией проекта.

На этом этапе нельзя добавлять крупные новые бизнес-сущности. Нужно аккуратно подготовить текущий код к будущему расширению.

Главный результат пункта:

- текущий upload flow продолжает работать;
- текущий document list/detail/search продолжает работать;
- текущая логика ADMIN / EMPLOYEE не ломается;
- department-based access не ломается;
- DocumentAccess не ломается;
- DocumentActivity не ломается;
- AI extraction / metadata parsing не ломается;
- ключевая бизнес-логика становится более аккуратно вынесенной в services;
- появляются базовые тесты или подробный manual-check.

## Главный принцип

Не переписывать проект.

Не создавать новую DMS-систему рядом со старой.

Не менять поведение ради красоты кода.

Если логика уже работает, её нужно переносить осторожно:

```text
старый view
↓
вынос части логики в service
↓
view вызывает service
↓
поведение для пользователя остаётся тем же
