# Stage 25 — AI Quality Upgrade / Улучшение ИИ-качества

## Цель этапа

Улучшить качество ИИ-обработки документов без изменения главного правила:

ИИ предлагает, человек подтверждает.

Запрещено автоматически применять ИИ-результаты к документу без ручной проверки.

## Текущий контекст

В проекте уже есть:

- ProcessingJob;
- ExtractedField;
- AI review page;
- apply confirmed fields;
- audit events для AI processing;
- access protection.

## Что улучшить

Усилить извлечение:

- даты документа;
- номера документа;
- типа документа;
- названия;
- краткого описания;
- контрагента;
- суммы, если применимо;
- признаков приложения/акта/счёта/договора.

## Связанные документы

На этом этапе можно добавить только ИИ-подсказку о возможной связи документов, но нельзя автоматически создавать связь.

Пример:

ИИ может предложить:

“Этот документ похож на приложение к договору №...”

Но пользователь должен вручную подтвердить связь через функцию связанных документов.

## Качество и безопасность

Если ИИ недоступен или ошибка парсинга произошла, загрузка документа не должна падать.

Все ИИ-предложения должны оставаться редактируемыми.

## Чего нельзя делать

- Не применять поля автоматически.
- Не создавать связи автоматически.
- Не заявлять 100% точность.
- Не использовать реальные клиентские документы без разрешения.
- Не начинать Stage 26.

## Тесты

Добавить tests:

1. AI parser создаёт suggestions.
2. Suggestions не меняют Document без apply.
3. Confirmed fields применяются.
4. Rejected fields не применяются.
5. Ошибка AI не ломает upload.
6. Возможная связь создаётся как suggestion, а не как реальная связь.
