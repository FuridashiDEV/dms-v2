# Stage 26 — Semantic Search and Document Intelligence / Поиск по смыслу и понимание документов

## Цель этапа

Улучшить пользовательский сценарий поиска по смыслу и похожих документов.

Важно: поиск по смыслу должен дополнять обычный поиск, а не заменять его.

## Текущий контекст

В проекте уже есть:

- extracted text;
- indexing service;
- Qdrant vector store;
- document list search;
- `/search/`;
- related documents после Stage 20;
- permissions and organization isolation.

## Что нужно улучшить

Добавить или улучшить:

- понятный режим поиска по смыслу;
- обычный текстовый поиск;
- фильтры;
- похожие документы;
- учёт связанных документов в карточке;
- объяснение, почему документ найден;
- безопасную работу при недоступном Qdrant.

## Как должно работать

Пользователь вводит запрос:

“договор по поставке оборудования”

Система должна уметь находить:

- договоры;
- приложения;
- акты;
- счета;
- документы со схожим содержанием;
- связанные документы.

## Права доступа

Поиск не должен показывать документы другой организации или документы без доступа.

Похожие документы также должны фильтроваться через access helpers.

## Чего нельзя делать

- Не показывать документы без прав доступа.
- Не делать semantic search единственным режимом.
- Не обещать идеальную точность.
- Не ломать обычный поиск.
- Не начинать Stage 27.

## Тесты

Добавить tests:

1. Обычный поиск работает без Qdrant.
2. Semantic search безопасно деградирует, если Qdrant недоступен.
3. Semantic search не показывает документы другой организации.
4. Similar documents не показывают недоступные документы.
5. Фильтры работают вместе с поиском.
