# Stage 24 — Notifications / Уведомления

## Цель этапа

Добавить базовую систему внутренних уведомлений для пользователей.

Уведомления должны помогать пользователю не пропустить важные действия:

- назначено согласование;
- документ требует проверки;
- контрагент открыл документ;
- контрагент оставил комментарий;
- контрагент принял документ;
- контрагент отклонил документ;
- ИИ-поля ожидают проверки.

## Что нужно реализовать

Добавить модель уведомления, если её ещё нет.

Минимальные поля:

- organization;
- recipient;
- actor, если применимо;
- notification_type;
- title;
- message;
- related_document;
- related_exchange;
- is_read;
- created_at;
- read_at.

## Интерфейс

Добавить:

- пункт навигации или иконку уведомлений;
- список уведомлений;
- отметку прочитано;
- счётчик непрочитанных уведомлений.

## События для уведомлений

На этом этапе создать уведомления для:

1. Назначения пользователя согласующим.
2. Комментария контрагента.
3. Принятия документа контрагентом.
4. Отклонения документа контрагентом.
5. Документа, ожидающего AI review.

## Права доступа

Пользователь видит только свои уведомления.

Пользователь не должен видеть уведомления другой организации.

Если уведомление связано с документом, ссылка должна быть доступна только при наличии доступа к документу.

## Чего нельзя делать

- Не подключать внешние push-сервисы.
- Не подключать email-рассылку без отдельного решения.
- Не отправлять secure portal tokens в уведомления.
- Не делать массовые рассылки.
- Не начинать Stage 25.

## Тесты

Добавить tests:

1. Уведомление создаётся при назначении workflow.
2. Уведомление создаётся при external comment.
3. Пользователь видит только свои уведомления.
4. Пользователь другой организации не видит уведомление.
5. Можно отметить уведомление прочитанным.
6. В уведомлениях нет secure tokens.
