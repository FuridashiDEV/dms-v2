# Stage 21 — Pre-Pilot Stabilization / Подготовка к пилоту

## Цель этапа

Подготовить текущий продукт к стабильной демонстрации инвестору, клиенту или пилотной организации.

Этот этап не должен добавлять крупные новые функции. Его задача — проверить и стабилизировать уже существующие пользовательские сценарии.

## Текущий контекст проекта

Проект уже имеет:

- документы;
- версии;
- доступы;
- аудит;
- ИИ-проверку;
- импорт;
- согласование;
- связанные документы после Stage 20;
- портал контрагента;
- B2B-обмен;
- сообщения обмена;
- доказательный пакет;
- usage tracking;
- аналитику;
- документацию;
- QA checklist.

## Основной сценарий для проверки

Нужно проверить и при необходимости исправить полный сценарий:

1. Вход в систему.
2. Открытие главной страницы.
3. Загрузка документа.
4. Открытие карточки документа.
5. Проверка защищённого просмотра и скачивания файла.
6. Проверка ИИ-предложений.
7. Подтверждение ИИ-полей.
8. Применение подтверждённых полей.
9. Добавление связанного документа.
10. Запуск согласования.
11. Утверждение или запрос изменений.
12. Отправка документа контрагенту.
13. Открытие портала контрагента без входа.
14. Скачивание документа контрагентом.
15. Комментарий контрагента.
16. Принятие или отклонение документа.
17. Экспорт доказательного пакета.
18. Открытие usage dashboard.
19. Открытие analytics dashboard.
20. Проверка audit events.

## Что нужно реализовать

Если в ходе проверки обнаружены мелкие ошибки, исправить их без изменения архитектуры.

Можно исправлять:

- сломанные ссылки;
- отсутствующие кнопки;
- некорректные переходы;
- пустые состояния;
- ошибочные сообщения;
- проблемы доступа;
- мелкие проблемы шаблонов;
- несогласованные названия в интерфейсе;
- ошибки, из-за которых demo-flow не проходит.

## Что нельзя делать

- Не добавлять новые крупные функции.
- Не переписывать интерфейс полностью.
- Не менять модели без необходимости.
- Не начинать интеграции.
- Не начинать платёжную систему.
- Не менять бизнес-логику ради косметики.
- Не начинать Stage 22.

## Результат этапа

После этапа должен быть понятный demo-ready flow.

Должно быть возможно показать продукт без ручного исправления данных в базе и без угадывания URL.

## Тесты

Добавить или обновить smoke/regression tests, если найдены проблемы.

Минимально проверить:

- document upload;
- document detail;
- related documents;
- AI review access;
- workflow access;
- exchange access;
- evidence export access;
- analytics access;
- usage dashboard access.
