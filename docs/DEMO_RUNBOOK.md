# Demo Runbook

## Цель презентации

Показать продукт не как “файлохранилище”, а как умный архив, который:

- понимает документ
- хранит его в правильном контексте
- быстро находит по смыслу
- отслеживает версии и риски

## Что проверить заранее

### Инфраструктура

- PostgreSQL доступен
- Qdrant отвечает на `localhost:6333`
- Ollama отвечает на `localhost:11434`
- модель `mistral` загружена
- миграции применены

### Команды

```powershell
python manage.py check
python manage.py migrate
python manage.py runserver
```

## Демо-поток

### 1. Главная

Покажите:

- количество документов
- активность пользователей
- две основные точки входа: загрузка и просмотр архива

### 2. Архив по папкам

Покажите:

- корневые папки отдела
- вход внутрь папки
- подпапки
- документы текущего уровня
- документы во вложенной ветке

### 3. Загрузка документа

Покажите:

- загрузку файла
- выбор отдела и папки
- архивные метаданные
- широкий список поддерживаемых форматов

### 4. Умная карточка

Покажите:

- `public_id`
- описание и архивные поля
- checksum и format risk
- AI-сводку
- предпросмотр
- версии
- связи документа
- похожие документы
- аудит действий

### 5. Поиск

Покажите:

- фильтрацию по реквизитам
- поиск по смыслу
- похожие документы

### 6. Продажный финал

Фраза для закрытия:

“Система не просто хранит файлы. Она понимает документы, связи, версии, контекст хранения и помогает находить нужное по смыслу.”

## План B

Если Ollama недоступна:

- показываем карточку без AI-сводки
- делаем акцент на архивных метаданных, версиях, папках и похожих документах, если Qdrant доступен

Если Qdrant недоступен:

- показываем обычный поиск, карточку, OCR и версии

Если OCR для конкретного файла не сработал:

- показываем, что архив все равно хранит файл, считает checksum и ведет карточку
